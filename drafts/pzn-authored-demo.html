Same-target precedence — IXP wins

This section carries BOTH data-pzn and data-exp, with no block scoping on either — so they target the SAME whole-section element. The authored contract's precedence rule applies: only the experiment runs here; the pzn-offer-slot placement is dropped entirely (see discover.js's sameTargetAsExp). If personalization had won instead, you'd see this text change on ties reload just like the section above — it never will.

How this works

scripts/personalization/discover.js collects every [data-pzn] section on the page (skipping one that also carries data-exp for the SAME target), resolves them all in ONE batched resolveDecisions call, and applies each via renderDecision's fragment scope (the same post-decoration, self-decorating swap the decisions-manifest lane uses). Separately, it collects every [data-exp] section and, for each, calls getAssignment then applies via renderDecision's section scope — which byo.js applies as an UNDECORATED swap, so scripts.js runs this lane BEFORE its own page decoration (see discover.js's header comment for why the two lanes need opposite timing, and why only the personalization lane is phase-split into an eager first-section pass and a lazy below-the-fold pass).

See documentation/byo-decision-engine.md in the vendored plugin for the hook contracts, and experience-workspace/skills/ add-personalization-experimentation.md for the authoring contract this page's markup follows.
