How this works

scripts/scripts.js's decorateSectionMetadata converts each .section-metadata block carrying a pzn/exp tag into data-pzn / data-exp attributes on its section (and removes the consumed block), before decorateMain and the discovery lanes run. Then scripts/personalization/discover.js collects every [data-pzn] section (skipping one that also carries data-exp for the SAME target), resolves them all in ONE batched resolveDecisions call, and applies each via renderDecision's fragment scope. Separately, it collects every [data-exp] section and, for each, calls getAssignment then applies via renderDecision's section scope — an UNDECORATED swap, so scripts.js runs that lane BEFORE its own page decoration (see discover.js's header comment for why the two lanes need opposite timing, and why only the personalization lane is phase-split into an eager first-section pass and a lazy below-the-fold pass).

See documentation/byo-decision-engine.md in the vendored plugin for the hook contracts, and experience-workspace/skills/ add-personalization-experimentation.md for the authoring contract this page's markup follows.
