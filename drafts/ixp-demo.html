Experiment-assignment (IXP) demo

This page wires Intuit's decision engine onto the vendored aem-experimentation plugin's getAssignment hook (scripts/personalization/byo.js): the engine owns the arm (bucketing/stickiness/exposure) for a natively-authored experiment — a Section Metadata block with Experiment / Experiment Variants rows, not a manifest sheet — and the plugin renders whichever variant the engine (here, a sticky demo mock) picked.

Try ?experiment=ixp-hero-test/challenger-1 or ?experiment=ixp-hero-test/control to force an arm (the plugin's own QA override), or no parameter at all to see the sticky demo mock (persisted in an ixp-arm-ixp-hero-test cookie) — reload a few times with no parameter and the same arm keeps showing. Open devtools while loading to confirm there are no console errors.

How this works

The engine owns the arm (getAssignment), and the page's own Experiment Variants metadata owns arm-to-content — there is no manifest sheet involved here, unlike the cell-resolution demo (pzn-cell-demo.html). This is a section-level experiment: the section above (the control content plus its Section Metadata block) is the control arm, and drafts/fragments/experiments/hero-challenger-1 is the sole challenger.

See documentation/experiments.md in the vendored plugin for the native authoring convention, and documentation/byo-decision-engine.md for the getAssignment hook contract.
